# AGENTS.md — Proposed Agent Notes

这些 Agent Note 是评审中的提案；这里没有任何东西已经发布。遵循[根说明](../../../AGENTS.md) 与 [Agent Note 格式](../README.md#the-file-format)。

## 为将要决策的读者写，不是为提出者写

一篇提案是写来被反驳的。读者在决定要不要建它，所以用问题和变更的形状开场，把细节花在「答应下来贵在哪、险在哪」。

这里用将来时是对的。迁移步骤、开放问题、「这个变更会做 X」都属于正文——一篇用过去时写的提案，读起来像一个没人做过的决策。

## 四个必需章节

- `## Problem` —— 动机，写成脱离解决方案也站得住。
- `## Proposal` —— 意图中的变更，点名它触碰的文件。
- `## Alternatives considered` —— 每个真实输掉的选项一个加粗引导段，以及为什么。见[强制要求](../README.md#alternatives-considered--mandatory)。
- `## Acceptance criteria` —— 意味着完成的可观察状态。「面板变快了」不是；「在 2000 条目的存储上打开面板在 200 ms 内完成」是。
- `## Risks` —— 同时覆盖可能出什么错，以及这个变更有意放弃了什么。

如果一篇提案会改动 [README.md](../../../README.md) 的某一节，点名那一节。一篇与契约矛盾的提案，要么是这棵树里最重要的一篇，要么是那一篇根本不该起草的。

## 提案不会永远躺着

一篇不再值得追的提案是**被否决**，不是删掉也不是归档：搬到 `rejected/`，把一句话原因放到 `Status:` 行，冻结正文。归档只属于已实现的 note。
